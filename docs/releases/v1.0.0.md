- Screenshot testing: `swiftshot verify` compares every screenshot with a baseline committed to the repository, pixel by pixel, and fails when something changed. Same commands for iOS, Android, Compose Multiplatform and Flutter.
- An HTML report shows each change next to its baseline, with the difference framed, filtered by language, device and appearance.
- On CI, `verify` comments the result on the pull request and shows it in the CI's own results. Detected: GitHub Actions, GitLab, Bitbucket, Bitrise, Codemagic, CircleCI, Azure Pipelines and Jenkins.
- A person accepts the changes on CI: a `/swiftshot accept` comment on GitHub, a manual job, pipeline or approval elsewhere. `swiftshot accept --from <report> --push` renders nothing; it commits the screenshots `verify` made. A CI never accepts on its own.
- Baselines are recorded on CI only, so results don't depend on the machine. The first baseline is accepted the same way.
- Recipes for every CI above in the wiki, and `llms-full.txt` for coding agents.
